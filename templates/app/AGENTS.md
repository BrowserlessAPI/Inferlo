# AGENTS.md

This is a [Inferlo](https://github.com/BrowserlessAPI/Inferlo) backend. Inferlo is a TypeScript backend framework designed so AI coding agents get things right the first time. Follow these rules.

## Before you change anything

```bash
npx inferlo describe --json   # every model, field, route, auth rule and AI alias
```

Read that instead of searching the codebase. After every change run:

```bash
npx inferlo check --json      # typecheck + load the app + tests, machine-readable errors
```

Do not finish until `inferlo check` passes.

## Layout

| File | What goes there |
|---|---|
| `src/models.ts` | Every model (`model("table_name", { ... })`) and the `models` array |
| `src/routes/<feature>.ts` | Routes for one feature, each one an exported `const` |
| `src/config.ts` | `settings`: every environment variable, validated at startup with `config({ schema, secrets })` |
| `src/app.ts` | `createApp({ models, routes, db, auth, ai })`. Import route modules with `import * as x` |
| `src/server.ts` | Starts the server. Keep it small |
| `test/<feature>.test.ts` | Tests using `app.request(path, { method, json, as: user })` |

## Rules

1. **One way to do each thing.** Routes: `route.get/post/put/patch/delete(path, options).handle(fn)`. Validation: `t.*` schemas. Database: `db.<table>.<method>`. AI: `ai.generate` / `ai.stream` / `ai.embed`.
2. **Routes are private by default.** A route without `auth` needs a signed-in user. Use `auth: "public"` only for routes anyone may call, and `auth: "<role>"` for role checks. Browser sign-in uses cookie sessions: `export const session = sessions({ secret: settings.SESSION_SECRET, user: ({ userId }, { db }) => ... })`, `createApp({ auth: session })`, `await session.signIn(ctx, user.id)` in the login route and `session.signOut(ctx)` in logout; browsers send the CSRF token in `X-CSRF-Token` or a `_csrf` form field on POST, PUT, PATCH and DELETE (403 IL3005 without it). Company single sign-on (Okta, Entra ID, Google Workspace, Keycloak) for browser apps is `export const sso = oidc({ issuer, clientId, clientSecret, session, userId: (claims, { db }) => ... })` with `routes: [..., sso]`, ending in that session (sign out with a POST form to `sso.logoutPath` with the `_csrf` field, which also signs out at the provider; Google's `hd` and Entra ID's `domain_hint` go in `authorizationParams`); return `null` from `userId` for unknown users and trust `claims.email` only when `claims.email_verified` is true. APIs whose users sign in with an identity provider (Auth0, Okta, Entra ID, Keycloak, Clerk) check its access tokens with `auth: jwt({ issuer, audience, user: (claims) => ({ id: claims.sub, roles: [] }) })`; never decode or verify JWTs by hand. Apps that sign in with Better Auth keep it and use `const session = betterAuthSession(auth, { user: ({ user }) => ({ id: user.id, email: user.email, roles: [] }) })` from `@browserlessapi/inferlo/better-auth` with `createApp({ auth: session, middleware: [session.middleware] })`; never write a second sign-in system next to it. Apps on Auth.js do the same with `authJsSession(Auth, authConfig)` from `@browserlessapi/inferlo/authjs` (add `id: token.sub` to the session in `callbacks.session`). Express apps on Passport.js mount the app with `toNodeHandler(app)` after `passport.session()` and use `auth: passportSession({ user: (u) => ({ id: u.id, email: u.email, roles: [] }) })` from `@browserlessapi/inferlo/passport`.
3. **Validate every input with a schema.** `body`, `query` and `params` options. Reuse model schemas: `Ticket.pick("title", "body")`, `Ticket.omit("ownerId")`, `.partial()` for PATCH. File uploads: `body: t.object({ avatar: t.file({ maxBytes: 2_000_000, types: ["image/png", "image/jpeg"] }) })` gives the handler a `File` (clients send `FormData`); several files are `t.array(t.file()).max(10)`. Never put `t.file()` in a model: keep the file with `ctx.storage` (`` await storage.put(`avatars/${user.id}`, body.avatar) ``, needs `createApp({ storage: diskStorage({ dir: "./uploads" }) })`, or `s3Storage({ bucket, region, accessKeyId, secretAccessKey })` for AWS S3, R2 and MinIO, `memoryStorage()` in tests; with S3, `await storage.url(key, { expiresIn: 300 })` is a signed download link) and its key in a `t.string()`; build keys from ids, never from the client's file name.
4. **Check ownership.** Fetch with `db.x.get(id)` (throws 404) and compare `ownerId` to `user.id`; throw `notFound()` when it does not match, so other users' ids are not revealed. When more than one rule decides access (owners, admins, teams), define named permissions once in `src/permissions.ts` with `export const access = permissions({ "notes.update": ({ user, note }) => note.ownerId === user.id || (user.roles ?? []).includes("admin") })`, pass `permissions: access` to `createApp`, and call `await access.authorize("notes.update", { user, note })` in routes and jobs (403 IL3004 when denied). Permissions that need only the user go on the route: `{ permission: "reports.view" }`; add `permissions: typeof access` to `Register` (with `import type`) so permission names are type-checked. When changes must be on record (who changed what), add `AuditLog` to the models and call `await audit("notes.update", { model: "notes", before: note, after: updated })` after the change, in routes and jobs (jobs pass `userId`).
5. **Related rows:** a `t.ref` field named `<name>Id` is a relation: `db.notes.findMany({ include: { owner: true } })` adds `note.owner` with one extra query, and `db.users.findMany({ include: { notes: true } })` adds `user.notes` (the rows that point to each user). Never load related rows in a loop. For lists clients page through, use `db.notes.paginate({ where, orderBy: { createdAt: "desc" }, cursor: query.cursor, limit: query.limit })`, which returns `{ items, nextCursor }`.
6. **Never write raw SQL with string concatenation.** Use the table methods. If you really need SQL, use `db.$sql(text, params)` with `$1` placeholders. Code that takes a pg client (Drizzle, Kysely, plain `pg`, and Knex queries with `.connection(client)`) gets it from `db.$pgClient()`, and inside `db.$transaction(async (tx) => ...)` from `tx.$pgClient()`, so it runs in the same transaction. Apps on postgres.js run Inferlo on their `sql` instance with `postgres({ pool: postgresJsPool(sql) })` from `@browserlessapi/inferlo/postgres-js` (never a second pool), and inside a transaction use `const { sql } = await tx.$pgClient<PostgresJsClient<ReservedSql>>()`. Prisma, TypeORM, Sequelize and MikroORM cannot join an Inferlo transaction: for a write across a Prisma, TypeORM, Sequelize or MikroORM table and an Inferlo model, use `db.$transaction` and write the other table with `tx.$sql`. Apps on MikroORM must set `schemaGenerator: { skipTables: [...models.map((m) => m.name), /^inferlo_/, "audit_log"] }`, or MikroORM's schema update drops Inferlo's tables.
7. **Model ids, timestamps:** every model already has `id`, `createdAt`, `updatedAt`. Never define them or send them as input.
8. **New field?** Add it to the model in `src/models.ts`, then run `npx inferlo db push` in development, or `npx inferlo db migrate <name>` to write a migration file for production (applied with `npx inferlo db migrate --apply`). Use `.optional()` or `.default()` for new fields on existing tables. Never edit `migrations/snapshot.json`, and never edit a migration file that has been applied (`--apply` warns with IL4018 and does not run the change): put changes in a new migration. Removing a model or field needs `npx inferlo db migrate <name> --allow-drop` (it deletes that data); never use it for a rename. Changing a field's type or default, making it required or optional, or changing an enum's values needs `--allow-change`; give a newly required field a `.default()` so existing NULL rows get a value, and before removing an enum value add an `UPDATE` in the new migration file (before its `ADD CONSTRAINT`) that moves rows off it (IL4021).
9. **New resource?** `npx inferlo add resource <plural_name>` generates the model and CRUD routes. Then edit them.
10. **AI calls** use aliases from `src/app.ts` (`model: "fast"`), never hard-coded provider model ids in routes. Use `output: schema` for structured data and `for: user.id` so usage is tracked per user. A provider without a built-in adapter (Mistral, Bedrock, Azure, Vertex, Groq, ...) is added through its Vercel AI SDK package: `providers: { mistral: aiSdk(createMistral({ apiKey: settings.MISTRAL_API_KEY })) }`, then aliases name `"mistral:<model id>"`. When the app uses LangChain agents, give them Inferlo's model and tools: `toLangChainModel(ai, { model: "fast", for: user.id })` and `toLangChainTools([getWeather, createNote], { ai })` from `@browserlessapi/inferlo/langchain`, never a second set of provider keys. To let the model act, pass routes as tools: `ai.generate({ prompt, tools: [createNote, getNote], for: user.id })`. Each tool call runs as the current user with that route's auth and validation. For work that is not a route (an external API, a calculation), make a function tool: `tool("getWeather", { description, input: t.object({ ... }) }).handle(async ({ input }) => ...)`. To send images: `ai.generate({ prompt, images: [{ url }] })` or `[{ base64, mediaType: "image/png" }]`. Give routes that call AI models, send email or check passwords a `rateLimit: { max, per, by }` (IL2005 is the 429 it returns). Streaming to a chat UI built with the Vercel AI SDK (`useChat`): `route.post("/chat", { body: uiChatBody }).handle(({ body, ai, user }) => ai.stream({ model: "fast", messages: fromUIMessages(body.messages), for: user.id }).toResponse({ format: "ai-sdk" }))`.
11. **Errors:** throw `notFound()`, `forbidden()`, `badRequest()` or `httpError(status, message)`. Every Inferlo error has a code (ILxxxx), a fix and a docs link: read the fix before changing code.
12. **Imports:** relative imports end in `.ts` (`import { Note } from "../models.ts"`).
13. **Configuration:** read environment variables only through `settings` from `src/config.ts`. A new variable is a new field in its `t.object({ ... })` schema (`.default(...)` or `.optional()` unless the app cannot start without it), and API keys, passwords and connection URLs go in `secrets` so they are never logged. Never read `process.env` in routes.
14. **Expose to AI agents:** add `tool: true` to a route to make it an MCP tool at `/mcp`. Same auth applies.
15. **Slow work after the response** (email, slow AI calls) is a background job: `export const x = job("send-email", { input: t.object({ ... }) }).handle(async ({ input, db, ai }) => { ... })` in `src/jobs.ts`, registered with `createApp({ jobs: [jobs] })`, queued with `await ctx.jobs.enqueue(x, { ... })`. Pass ids in the input, not rows. In tests, run queued jobs with `await app.jobs.runDue()`. Jobs run in the server process (`app.jobs.start()` in `src/server.ts`); with `createApp({ jobQueue: { store: "database" } })` they are kept in Postgres (or with `createApp({ redis, jobQueue: { store: "redis" } })` in Redis, or in an existing BullMQ queue with `jobQueue: { store: bullmqJobStore(queue, worker) }` from `@browserlessapi/inferlo/bullmq`) and `npm run worker` (`inferlo worker`) runs them in separate processes. Scheduled work is a cron next to its job: `export const nightly = cron("0 3 * * *", cleanupJob)` (UTC; the job's input must be `t.object({})`). When other parts of the app react to something that happened, publish an event instead of enqueuing each job: `export const orderPaid = event("order.paid", { payload: t.object({ ... }) })` in `src/events.ts`, jobs subscribed with `on(orderPaid, sendReceipt)` (the job's input is `orderPaid.payload`) in `src/jobs.ts`, and `await ctx.events.publish(orderPaid, { ... })` after the change is saved. To send events to other services, give each service a `name` and set `createApp({ name, redis, events: { transport: "redis" } })`; subscribers use the same `on(event, job)`.
16. **Security headers and health:** every response already gets security headers (CSP, HSTS over HTTPS, nosniff, frame and referrer policies) and `GET /health` and `GET /ready` are built in (`health: true` in `src/app.ts`). Change a header with `createApp({ secureHeaders: { "Content-Security-Policy": "..." } })` instead of setting it in every route, never turn them all off without a proxy that adds them, and never add your own `/health` route. On SIGTERM, `src/server.ts` calls `app.close()`, which finishes in-flight requests and jobs first. Prometheus metrics (`GET /metrics`: requests, jobs, AI calls, tokens and cost) are served when `METRICS_TOKEN` is set; never add your own `/metrics` route. Logs go through Inferlo's logger (request ids, redaction); to send them to pino, use `logger: pinoLogger(log)` from `@browserlessapi/inferlo/pino`, never `logger: pino()` directly (IL6053). To report errors to Sentry, pass `onError: sentryOnError(Sentry)` from `@browserlessapi/inferlo/sentry` to `createApp`; never wrap handlers in try/catch just to report errors.
17. **Large apps: feature modules.** When the app grows to several features, group each feature's models, routes and jobs in `src/<feature>/module.ts` with `export const billing = module("billing", { imports: [users], models: [...], routes: [routes], jobs: [jobs], provides: { createInvoice } })` and register it with `createApp({ modules: [users, billing] })`. A module that uses another module's models or `provides` lists it in `imports` (IL6023 and IL6024 tell you when one is missing). Call other modules only through their `provides`; never import their internal files. Keep every model in `Register` in `src/models.ts`.
18. **Replacing a route:** do not delete a route clients use. Add the new one and mark the old one `deprecated: { since: "YYYY-MM-DD", sunset: "YYYY-MM-DD", link: "https://..." }` in its options; it then sends the standard Deprecation and Sunset headers and is marked in OpenAPI and MCP. Remove it after the sunset date. For a breaking change to many routes, publish a new API version instead: `createApp({ routes: [apiVersion("v1", [notesV1]), apiVersion("v2", [notes])] })` serves them under `/v1` and `/v2`, each with its own OpenAPI document (`/v1/openapi.json`); write route paths without the version prefix.
19. **Caching:** for results that are slow or expensive to compute, use the built-in cache instead of a module-level `Map`: `` return cache.getOrSet(`notes:stats:${user.id}`, { ttlMs: 60_000, tags: ["notes"] }, () => computeStats(db, user.id)) `` in routes and jobs (`ctx.cache`), and `await cache.invalidate("notes")` after notes change. `ttlMs` is required; put the user id in the key of anything that differs per user; values come back as JSON (dates as strings). To cache a whole GET route instead, add the route option `cache: { ttlMs: 60_000, tags: ["notes"] }` (one response per user by default; `by: "public"` only for data that is the same for everyone) and invalidate the tag where the data changes. With several instances, use `createApp({ cache: { store: "database" } })`.
20. **Calling another Inferlo service:** `const tickets = serviceClient({ baseUrl: settings.TICKETS_URL, token: settings.TICKETS_TOKEN })`, then in a handler `await tickets.call(getTicket, { params: { id }, ctx })` with the other service's route imported, so the call is typed. Catch `ServiceCallError` and check `error.remoteStatus` for answers you expect (404). Never build these URLs with `fetch` by hand. When the app uses `tracing: { api: otel }`, pass the same `tracing` to `serviceClient` so calls join the trace.
21. **Data of many organisations (multi-tenant):** give the signed-in user a `tenantId` (the organisation's id) and make tables whose rows belong to one organisation tenant-scoped: `model("projects", { ... }, { tenant: true })`. `ctx.db` then filters every query by and stamps every insert with the user's tenant, so never add `tenantId` to a `where`, a body schema or an insert. Jobs queued (or events published) by a request run for the request's tenant: their `ctx.db` is scoped the same way, so do not pass the tenant id in the job input. In scripts use `app.db.$tenant(tenantId).projects`, and `app.jobs.enqueue(job, input, { tenantId })`. For limits and caches shared by an organisation use `rateLimit: { max, per, by: "tenant" }` and `cache: { ttlMs, by: "tenant" }`; `ctx.audit` records the tenant itself.
22. **Live updates over WebSockets:** `export const chat = route.ws("/chat", { message: t.object({ text: t.string().max(2000) }), rateLimit: { max: 60, per: "minute" } }).handle(async ({ message, user, db, socket }) => ...)` in a routes file, registered like other routes. Return a value to reply with JSON, or call `socket.send(data)` for several messages; stream a model's answer with `await socket.stream(ai.stream({ model: "fast", prompt, for: user.id }))`. Auth works as for HTTP routes (browsers authenticate with cookie sessions); never add a second WebSocket server or library. For live updates, ``socket.join(`project:${id}`)`` in the WebSocket handler (after checking the user may see it) and ``await sockets.broadcast(`project:${id}`, data)`` from any route, WebSocket handler or job; rooms are per tenant, and with more than one instance add `sockets: { transport: "redis", subscriber: await redis.duplicate().connect() }` next to `redis` in createApp. Test with `await app.listen(0)` and `new WebSocket(url)`.
23. **Response schemas:** give routes whose answer clients rely on a `response` schema (`route.get("/me", { response: t.object({ id: t.uuid(), email: t.email(), name: t.string() }) })`) and return exactly those fields, never a whole row. Outside production Inferlo checks answers against it and logs IL2016 for a missing, wrong or extra field; tests use `createApp({ validateResponses: "error" })` so a mismatch fails.
24. **Requests that must not run twice** (payments, orders, sending email) take an idempotency key: `route.post("/orders", { body: NewOrder, idempotency: true })`. Clients send a new random `Idempotency-Key` header per request and the same one when retrying; repeats get the first answer. Never build your own "already processed" table for this.

## Testing

```ts
const res = await app.request("/notes", { method: "POST", json: { title: "Hi" }, as: user });
const note = await readJson(res, 201);   // from "@browserlessapi/inferlo/testing"
```

Use `memory()` for the database and `mockProvider()` for AI in tests.
